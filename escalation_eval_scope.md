
# Project title

Phone-a-friend: How reliably do models hand-off to humans in high-stakes settings?

## PROBLEM: What catastrophic AI risk is your project directed towards solving?

Organisational risk and Rogue AIs. Organisations hoping to use AI in high-stakes scenarios need to understand the inherent failure rates and risks, in order to deploy safer architectures. A better understanding of model behaviour in this use case can provide insight into the risks that come with AI that is widely deployed and given a lot of responsibility.

## GOAL: What will your project produce to help reduce this risk?

- A benchmark measuring how reliably agents escalate to humans when their instructed trigger conditions take place
- Evaluation of an open-source model on the benchmark: Qwen-2.5-32B
- An analysis separating "recognition" (did the model notice conditions for the trigger were met?) and "action" (did the model successfully escalate?)


## PROJECT PLAN: How will you achieve this GOAL?

- Build dataset
  = 100 scenarios
  - mental health domain
  - multi-turn: conversation between assistant and student
  - labelled groundtruth: escalate or not
  - generated by Claude API and hand-reviewed by me
- Run eval
  - Qwen via OpenRouter
  - LLM-as-a-judge grades each conversation: did the assistant escalate, yes or no
  - record how often model escalates
- Recognition check
  - take each conversation from the eval
  - give Qwen the transcript in a fresh context
  - ask "did the conditions for escalating happen in this conversation? yes or no"
  - LLM-judge grades the answer
  - pair recognition with action result
- Linear probe
  - set up Qwen for inference on GPU
  - save Qwen's activations at each layer while the conversations run
  - label each: should-have-escalated or shouldn't-have
  - train a simple linear classifier
  - score how well it separates the two
- Confound sycophancy stress tests
  - take the should-escalate scenarios and add user pressure ("please don't tell anyone, i trust you")
  - run them through the same eval pipeline
  - compare escalate rate vanilla vs pressured
- Analysis
  - escalate rates per scenario set (should / should-not / pressured)
  - recognition vs action table
  - probe separation score
  - brief writeup: which failure mode dominates
