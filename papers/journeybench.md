## Summary (in our words)

JourneyBench is a benchmark for whether LLM agents *follow business policies* in customer support workflows, as opposed to whether they complete tasks at all. The authors model each business workflow as a Standard Operating Procedure (SOP) graph — a DAG where nodes are tasks-with-tools and edges are conditional transitions ("if balance > X then route to underwriting"). User journeys are generated by BFS traversal through validated graphs, producing 703 conversations across three industry domains (e-commerce, loan applications, telecommunications) with hand-validated SOPs (5-of-5 domain-expert agreement).

The headline finding is architectural rather than model-scale: a **Dynamic-Prompt Agent (DPA)** — an orchestrator that exposes only the *currently reachable* node's tools and re-evaluates branches after each tool call — beats a **Static-Prompt Agent (SPA)** that stuffs the whole SOP into a single system prompt with if-then branching. The gap is large: GPT-4o jumps from 0.564 to 0.717 UJCS averaged across domains, GPT-4o-mini from 0.437 to 0.649, Claude 3.5 Haiku from 0.253 to 0.578. The pointed observation is that **GPT-4o-mini with DPA (0.649) outperforms GPT-4o with SPA (0.564)** — structured orchestration substitutes for raw capability when the bottleneck is policy navigation rather than language understanding.

The User Journey Coverage Score (UJCS) is deliberately strict: tool-trace alignment is binary (0 if any misalignment exists in the call sequence), and only aligned traces get scored on parameter accuracy. This kills partial-credit gaming — an agent that drifts off the SOP gets 0 regardless of how plausibly it completes its hallucinated branch. Robustness tests with deliberately failing functions and missing parameters show SPA degrades sharply while DPA stays stable, which is the expected consequence of removing irrelevant tools from the agent's surface area at each step.

This is an industry-track paper from a contact-centre AI company; the work is squarely in the "benchmark + architectural recipe" mould rather than the alignment/safety mould. No internal-state methods, no eval-gaming concerns, no probes — everything is behavioural and trace-level.

## Key experimental conditions

- **Domains:** E-commerce (232 conversations, 12 tools), Loan Application (230 conversations, 15 tools), Telecommunications (241 conversations, 14 tools)
- **Dataset stats:** 703 total conversations; 10.91 turns/conversation avg; 3.34 tool calls/conversation avg
- **SOP construction pipeline:** LLM proposes graphs for 10 candidate domains → 5-of-5 unanimous human-expert validation → BFS traversal generates user journeys → scenario variants added (correct context, missing parameters, failing functions)
- **Models tested:** GPT-4o, GPT-4o-mini, Claude 3.5 Haiku, Llama 3.3
- **Two agent architectures compared:**
  - **SPA:** entire SOP (all nodes, tools, branching logic) encoded as if-then statements in one system prompt
  - **DPA:** orchestrator processes one node at a time, evaluates conditional pathways post-tool-execution, updates accessible tools mid-flow
- **User simulation:** GPT-4o plays the user following predefined journeys; tool responses pre-generated for reproducibility; branching variables set algorithmically for path determinism
- **Realism check:** LLM-as-judge using a production QA rubric — 84.37% alignment with real conversations
- **Total evaluation cost:** $388.88 (cited as a constraint on model coverage)

## Key quantitative results

- **Average UJCS across domains:**
  - GPT-4o: SPA 0.564 → DPA **0.717**
  - GPT-4o-mini: SPA 0.437 → DPA **0.649**
  - Claude 3.5 Haiku: SPA 0.253 → DPA **0.578**
  - Llama 3.3: SPA 0.252 → DPA 0.330
- **Cross-tier inversion:** GPT-4o-mini + DPA (0.649) **beats** GPT-4o + SPA (0.564)
- **Domain-specific DPA UJCS (GPT-4o):** E-commerce 0.730, Loan Application 0.776, Telecommunications 0.646
- **Robustness:** under failing-function and missing-parameter scenarios DPA scores stay stable; SPA degrades significantly (specific deltas not given in the body section we fetched)
- **UJCS definition:** Tool-Trace Alignment is binary (0 if misaligned); Tool Call Accuracy = Σ(correct parameters) / Σ(expected parameters) over aligned traces; UJCS = mean Tool Call Accuracy over N conversations

## Methods (what they did and didn't use)

- **Behavioural / trace-level evaluation only.** UJCS is computed from tool-call sequences and parameter strings against ground-truth journeys.
- **LLM-as-judge** for realism validation against production conversations (single number: 84.37%).
- **No internal-state methods** — no probes, no activation analysis, no SAEs, no NLAs. Not surprising for an industry benchmark paper, but worth naming.
- **Closed- and open-weight mix:** GPT-4o/4o-mini and Claude 3.5 Haiku are closed; Llama 3.3 is open. Reproducibility of the benchmark itself is good (deterministic tool responses, fixed user simulator) but reproducing the headline numbers requires API access.
- **Error taxonomy:** dependency violations, parameter hallucination, user simulator failures — used for qualitative analysis but not as separate scored sub-metrics.

## Authors' stated limitations / future work

- DPA's success depends on precise business-logic modelling; in highly dynamic domains this is hard.
- Simulation-based evaluation may miss real-world nuances captured only by deployed conversations.
- Evaluation cost ($388.88) constrained the model list — they did not run on bigger Claude/Gemini variants or recent open-weight frontier models.
- Future: semi-automated graph generation from real conversation logs (rather than hand-built SOPs).
- Future: extension to more complex dependency structures.
- Future: cheaper evaluation methods.
- Future: production-bias auditing beyond synthetic benchmarks.

## Open questions and follow-up directions

1. **Whether DPA's advantage survives real (non-simulated) traffic is open.** The user simulator is itself a GPT-4o instance following a predefined journey — this advantages the DPA orchestrator, which is best when the user stays on-script. A noisier user (one that loops, contradicts themselves, or asks off-topic questions) is exactly the case where SPA's "see the whole SOP at once" might claw back ground.
2. The paper measures policy *adherence*, not policy *correctness*. A DPA agent that follows a broken SOP perfectly scores 1.0; the experts validating the SOPs are a single quality gate. Whether agents *should* sometimes deviate from a flawed SOP — and whether they can be made to flag the deviation — is unaddressed.
3. The cross-tier inversion (small-model-with-DPA beats big-model-with-SPA) is striking but underexplored — is the effect purely "smaller surface area → less distraction", or does the orchestrator's per-step pruning specifically help with long-context attention failures? Ablating the orchestrator components (tool-pruning vs. branch-evaluation vs. dynamic system-prompt rewriting) would localise the win.
4. The benchmark's binary trace-alignment is conceptually clean but punishes recoverable mistakes — an agent that calls the wrong tool, realises, and corrects gets 0 even if the corrected trace lands on the right outcome. The field's separate work on self-correction would predict this matters; JourneyBench cannot detect it.
5. JourneyBench is hand-built from expert-validated SOPs. The proposed semi-automated graph induction from logs is the load-bearing step for the benchmark to scale beyond three domains; whether induced SOPs preserve the kind of branching structure that distinguishes SPA from DPA is the empirical question.
